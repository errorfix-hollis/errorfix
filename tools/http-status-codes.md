## The five classes

| Class | Meaning | Whose problem? |
|---|---|---|
| 1xx | Informational, request continues | nobody |
| 2xx | Success | nobody |
| 3xx | Redirect: look at the `Location` header | usually configuration |
| 4xx | The request was wrong: URL, auth, body, size, rate | the client (or how the client is configured) |
| 5xx | The server or something behind it failed | the server or proxy |

## 502 vs 503 vs 504

These three come from a **proxy or load balancer** (nginx, Apache, AWS ALB, Cloudflare) in front of your application, not from the application itself:

- **502 Bad Gateway**: the proxy reached the backend but got garbage or a dropped connection, or could not connect at all. The app crashed, is not listening, or listens on a different port/socket. See [fixing 502 Bad Gateway](/web/web-nginx-502-bad-gateway/).
- **503 Service Unavailable**: no healthy backend is available (all down, overloaded, maintenance mode, Kubernetes pods not ready).
- **504 Gateway Timeout**: the backend accepted the connection but did not answer in time. See [fixing 504 Gateway Timeout](/web/web-504-gateway-timeout/).

Check the proxy's error log first (`/var/log/nginx/error.log`): it says exactly which upstream failed and why.

## 401 vs 403

**401 Unauthorized** really means *unauthenticated*: no credentials, or bad ones. Logging in or sending a valid token fixes it. **403 Forbidden** means the server knows who you are (or does not care) and still refuses: file permissions, IP rules, a WAF, missing directory index. See [nginx 403 Forbidden](/web/web-nginx-403-forbidden/).

## Checking a status code

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://example.com/   # just the code
curl -sSI https://example.com/                                     # headers only
curl -sSIL https://example.com/                                    # follow redirects
```

In the browser, open DevTools → Network and look at the *Status* column. Codes in the 52x range and 499 are not in the HTTP standard; they are generated by Cloudflare and nginx and are marked as non-standard in the table above.
